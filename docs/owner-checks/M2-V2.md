## Foreground Glyph mirror

The official Nothing SDK 2.0 AAR is fetched by Gradle's downloadGlyphSdk task from its immutable release-artifact commit URL and verified against SHA-256 329393019db5f0f987c6245855d13fa273d06756c68829ca0f6ae686ba336da1. The AAR is not committed. Every preBuild, including CI, depends on the task. Native Binder entry points are kept through R8.

The main Pocket screen and power-button panel share a foreground lease. Listening/speaking breathe on the C strip, asking pulses on A, and the real three-second elapsed countdown fills C. Idle/background turns off and closes the session. A stale window cannot close a newer foreground window's session. Non-Nothing and unsupported devices quietly do nothing. Phone (3a)'s LEDs are physically white: they cannot produce green/amber light; the LCD retains those colours and the patterns mirror their meaning.

Android 16+ removed Nothing's API-key restriction. The documented compatibility value test is included, not a private key. On older Nothing OS, official SDK authorization or Nothing's development mode is needed. Official development-mode command, if the owner uses that older OS:

```sh

```

Nothing documents a 48-hour development-mode expiry. See the official Glyph Developer Kit README. No unsupported system permission is silently granted by the app.

## Automatic Jev decisions

The pinned public Jev GGUF and native adapter remain the runtime. Automatic typed choices are ON at stable softmax confidence >= 0.85. Below the threshold, invalid scores, missing model or failed runtime ask one short spoken question. The app neither reads nor requires a production precision certificate. The confidence is not a measured accuracy claim. Gemma remains the language/vision engine.

A model-selected local, sensitive or outbound phone action is announced and waits the full three seconds after speech. Read-only lookups are immediate and keep the turn's action marker; later actions still wait. Stop, cancel or a tap cancels; yes cannot shorten it. Banking blocks and fresh spoken-yes deletion checks remain. Ordinary deterministic local commands retain their prior policy. Non-call countdowns say ACTING; the exact approved CALLING F4 remains unchanged.

Every attempt appends input/options, raw verdicts, confidence, threshold, selected/asked result, reason and latency to the private no-backup file decision/decisions.jsonl. Engine-owned session identity links subsequent tool observations (including denials and failures), cancellation and the next owner answer to decision IDs. The log is append-only and never uploaded or automatically deleted. An unwritable decision log asks instead of selecting automatically. Existing old certificate files are ignored and not silently erased. Report-only calibration scripts remain for future analysis; they do not gate runtime choices.

## CPU smart-turn

Gradle's downloadSmartTurnModel task fetches smart-turn-v3.2-cpu.onnx, 8,679,182 bytes, at revision f766f81d3cfdf7737ac64aad813d91bbfd56bf93, SHA-256 2bb026316b14a660486a75b1733cd3fbab8c2fd0314dc9af7be49f8cca967e4f. It is packaged for offline ONNX Runtime Android 1.28.0 CPU inference with one thread. Neither model weights nor the AAR are committed.

Model warm-up and inference run off the UI/recording threads. The complete feature/inference call has a 150 ms budget. Load failure, malformed score, timeout or a completed result over that budget automatically uses 700 ms silence for that listening session. The next session can use the cached model normally. Resumed speech invalidates a stale endpoint. Short utterances retain enough PCM for the existing one-second speaker check. Intermediate Android recognition segments do not dispatch actions; they are buffered until the endpoint closes input. Unsupported segmented recognizers retry once using the platform fallback. Recognition implementations may ignore optional endpoint hints; actual Phone (3a) behavior remains a handset check. The existing 15-second recording cap remains.

All 64,000 bins in each of three independently frozen Whisper/NumPy feature tensors match the unchanged 0.0005 tolerance. The reproduction script regenerates their exact hashes in a fresh directory. A host-only CPU model run confirmed float[batch,80,800] input and finite sigmoid completion output. No handset latency or semantic-accuracy number is claimed. See training/turn/README.md for details and reproduction.
