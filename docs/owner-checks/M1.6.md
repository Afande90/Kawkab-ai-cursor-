1. Do the signing-key steps below once (25b). Until then each new APK needs an uninstall first.
2. Open the repository's Releases page, download the newest `build-…` pre-release `.apk` and install it.
3. Type "set a timer for 2 minutes". It should start at once with an Undo chip. Tap Undo.
4. Type "call" and a first name shared by two contacts. Chips should appear; tap one, then the confirmation card.
5. Write one message in Sudanese Arabic and one in English. Each reply should stay in that language.
6. With Gemma 4 E4B active on a phone with less than 16 GB, send "hello". If it cannot allocate, the chat should say it switched to E2B and still answer.
7. Turn on the accessibility service and switch between apps for a minute. Switching should feel as smooth as with the service off.
8. Long-press the power button (after making Kawkab the assistant) and start conversation mode. Talk, then talk over its reply; it should stop and listen.
9. Settings → Phone access: every item should read on or off with one button to fix it.
10. About → Check for updates. It should say you have the newest build, or offer "Download build-…".
11. Optional, with models pushed by `adb` to `/data/local/tmp/kawkab-models`: run `ModelSwitchReplyTest`.

## One fixed signing key (task 25b): steps for the owner

Every CI APK is signed with a new throwaway key until these secrets exist, so each update needs an uninstall, which deletes the models and your data. The build machine cannot create repository secrets, so this step is yours. Do it once.

1. On your laptop, create the keystore (keep the passwords somewhere safe):

   ```
   keytool -genkeypair -v -keystore kawkab-release.jks -alias kawkab -keyalg RSA -keysize 4096 -validity 10000
   ```

2. Turn it into one line of base64.
   - Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("kawkab-release.jks")) | Set-Content keystore.b64`
   - Linux or macOS: `base64 -w0 kawkab-release.jks > keystore.b64`

3. Read its fingerprint: `keytool -list -v -keystore kawkab-release.jks -alias kawkab`. Copy the `SHA256:` value, remove the colons and write it in lower case.

4. On GitHub, open the repository → Settings → Secrets and variables → Actions.
   - New repository secret `RELEASE_KEYSTORE_BASE64`: the contents of `keystore.b64`.
   - New repository secret `RELEASE_KEYSTORE_PASSWORD`: the keystore password.
   - New repository secret `RELEASE_KEY_ALIAS`: `kawkab`.
   - New repository secret `RELEASE_KEY_PASSWORD`: the key password.
   - Variables tab, new repository variable `RELEASE_CERT_SHA256`: the fingerprint from step 3.

5. Keep `kawkab-release.jks` backed up off the repository (for example on a USB stick). Never commit it: the repository is public. If it is lost, no later build can update the installed app.

6. After the next green push, uninstall the old app one last time and install the new APK. From then on each new APK installs over the old one and keeps the models and data.

The Check's APK job already uses these secrets when they exist and warns when they do not.
