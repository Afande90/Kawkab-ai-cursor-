## Follow-up changes

- Both typed and spoken call/message countdowns announce the action and listen for stop/cancel. Partial recognition can cancel before the recognizer finishes a whole turn. Silence and unrelated speech keep the cancel listener active. An approval cannot shorten the three-second window.
- Calls go through Telecom. If Telecom refuses the call, the fallback targets the default Phone package explicitly; no implicit call intent is sent when a default is missing.
- Contact questions use numbered names and a spoken answer, including after a typed request. Remembered choices appear in Growth and can be removed.
- Once Kawkab holds the assistant role, its Phone access button opens an exported power-button/gesture settings page where available, falling back to assistant settings. Android still owns the physical power-button mapping.
- Local crash reports retain classes, stack frames and signals, excluding native abort messages and free-form Android exit descriptions that might contain personal content.
- Recognition uses the on-device recognizer only. Speech output requires an offline voice. Missing offline voice data does not permit a network fallback.

## Optional phone observations

These are observations, not release gates imposed on the owner:

1. With microphone permission granted and wake enabled, open the app. A wake failure should leave the app open with a notice; an early app crash should result in safe mode next time.
2. Type a call request and say "stop" during the countdown. No call should start. Repeat without cancellation: the Phone service should place it without an app chooser.
3. Resolve an ambiguous name by speaking the contact name or number in the list, repeat the original request, then remove the remembered choice from Growth.
4. In Phone access, review the assistant role and set Nothing OS's press-and-hold power gesture to Digital assistant. The Quick Settings tile and Ask Kawkab shortcut remain fallbacks.
